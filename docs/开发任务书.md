# 开发任务书 — P0 提案工作台

> 读者：DS Harness
> 目标：在 `src/` 做一个可现场演示的静态 Web 工作台，不依赖后端、不依赖网络。
> 先读 `HANDOFF.md` 第 5/6/7 节；本文件是验收口径。
> **当前默认：银行（浦发 / 3 个真实支行）；医院（美华/嘉会/和睦家）是第二套完整样板。**

---

## 1. 交付物

```text
src/
├─ index.html      # 单页工作台
├─ styles.css      # 视觉（参考 docs/01_项目介绍.html）
├─ app.js          # 交互、预算滑块、视图切换、导出
├─ engine.js       # 选点/组合/报价（纯函数，确定性）
├─ data.js         # 可选：由 data/*.json|csv 生成的静态数据
└─ README.md       # 运行说明 + 数据来源 + 已知限制
```

要求：

- 无 npm、无构建步骤；`python -m http.server 8788` 后打开 `/src/index.html` 即可。
- 无外部 CDN、无地图瓦片、无网络请求（数据从同源 `../data/` fetch，或内嵌 `data.js`）。
- 中文界面；桌面 1440×900 优先，兼容 390px 手机。
- 不修改 `src/` 以外任何文件。

## 2. 页面结构

### 2.1 顶部

- 左：`新云 · 提案工作台` / `MEDIA FLIGHT DECK`
- 右：数据快照时间（来自 `inventory_live.json.fetchedAt`）+ `2027 Q2`

### 2.2 左栏：输入

| 控件 | 默认 | 说明 |
|---|---|---|
| 行业 | 银行保险 | 下拉：银行保险/食品饮料/保健品/私立医院/乐园；P0 默认银行，医院已就绪 |
| 品牌 | 浦发银行 | 银行预设浦发；医院预设美华/嘉会/和睦家 |
| 预算 | 200 万 | range 100–500，step 10 |
| 媒体 | 地铁+公交 | 复选：公交 / 地铁 |
| 档期 | 2027-04-01 ～ 2027-05-12 | 下拉预设：Q2 6 周 / 暑期 8 周 / 国庆 4 周；P0 用 Q2（06 周，落在已验证窗口内） |
| 生成 | 按钮 | 触发重算（也可自动重算） |

### 2.3 中栏：地图

- 上海示意 SVG（可复用 `docs/01_项目介绍.html` 的地图路径/节点）。
- 锚点：默认陆家嘴 3km；银行 100/200/500 万单点；切医院时用美华 3km，500 万也用美华单点（不切并集）。
- 覆盖圈：半径 1000m/3000m。
- 选中媒体：公交线路/地铁口用橙色高亮；候选用灰色。
- 图例 + `SCHEMATIC / NOT TO SCALE`。

### 2.4 右栏：方案摘要

- 预算、公交数量、地铁数量、周期、商圈数、预估触达。
- 媒体配比条（地铁/公交）。
- 预算使用率（净价/预算），超预算红色。
- 数据来源：红豆快照时间、覆盖 CSV 文件名。

### 2.5 方案表

列：

```text
媒体类型 | 媒体名称 | 级别 | 数量 | 空车数 | 单价(元/月) | 周数 | 刊例小计 | 折扣 | 净价 | 最近距离 | 最近站点 | 选择理由
```

- 按净价/触达效率排序。
- 每行可展开“证据”：查询日期、合同/预定、覆盖锚点、为什么选它。
- 显示“库存快照：2026-11-21 11:31”。

### 2.6 报价卡

```text
媒体刊例小计
− 折扣（92%）
+ 制作费
+ 监测费（可设 0 或 2%）
= 净价
预算余额
```

- 折扣默认 1.0（按刊例）；0.92 是示例假设，放在 `PRICING.discount`，可切换。
- 显示“刊例口径，不构成合同报价”。

### 2.7 视图切换

- 客户视图：策略、组合、排期、报价；隐藏折扣底线/毛利。
- 销售视图：空车数、合同/预定、折扣底线（88 折）、替补池、锁定建议。
- 同一份数据，两种文案。

### 2.8 导出

- `导出 CSV`：方案表 + 报价汇总；文件名含行业/预算/日期。
- `导出 HTML`：把当前方案渲染成一份可打印的独立 HTML（内联样式），至少包含封面、策略、清单、排期、报价、监测承诺。
- P0 可用 `window.print()` 兜底；P1 再做单文件导出。

## 3. 生成逻辑

### 3.1 读取数据

```js
const inv = await fetch('../data/inventory_live.json').then(r => r.json());
const manifest = await fetch('../data/manifest.json').then(r => r.json());
const aliases = await fetch('../data/bus_aliases.json').then(r => r.json());
const stationMap = await fetch('../data/metro_station_map.json').then(r => r.json());
// 默认陆家嘴 3km（银行）；可切换美华/嘉会/和睦家/人民广场/迪士尼/徐家汇
const coverage = await loadCoverage('../data/coverage/覆盖分析_陆家嘴_3000米.csv');
const geo = await fetch('../data/geo/lujiazui_media_geo.json').then(r => r.json());
const footfall = await fetch('../data/footfall/lujiazui_202305.json').then(r => r.json());
```

- `inventory_live.json`：bus 431 / metro 861；字段见 HANDOFF 5.1。
- `manifest.json`：列出所有覆盖文件（anchor/radius/count）。
- `bus_aliases.json`：156 个覆盖名，152 匹配；866/986/南龙/840 已补别名。
- `metro_station_map.json`：31 站/93 口的查找表（24 站在库；世纪大道、北新泾、宝山路、真北路、虹桥路、虹漕路、迪士尼 7 站不在库）。
- 覆盖 CSV：新文件第一行就是表头；若首行是 `汇总分析` 则跳过；坐标去 `="..."`。
- `geo/lujiazui_media_geo.json`：70 条公交折线 + 1,779 个站点 + 49 个地铁口坐标；可直接画真实线路（GCJ-02 坐标，示意地图直接用）。
- `geo/<anchorId>_media_geo.json`：人民广场/徐家汇/美华/迪士尼的公交几何（66/31/30/31 条），字段与陆家嘴对齐；`metro` 为空，地铁用 coverage 站点坐标。当前 anchorId：`renmin-guangchang`、`xujiahui`、`meihua`、`disney`。
- `footfall/lujiazui_202305.json`：按线路名/站点+出口匹配 `dailyReach`（2023-05），无数据就显示“无数据”。

### 3.2 候选匹配

- 公交：`aliases.aliases[覆盖媒体名称].inventoryName` → `inv.bus.lineName`；同一线路可能有多条媒体形式，保留 `freeCount` 最大的或按 `mediaName` 分组。
- 地铁：覆盖结果是线路/站点级；用 `stationMap.stations[最近站点].exits` 展开成具体出入口，按 `grade` + `freeCount` 选 1–2 个口。
- 过滤：`freeCount >= 1`；`grade` 非空；`inventoryName`/`inInventory` 为真。
- 未匹配的候选不要静默丢弃：显示“覆盖候选 X / 红豆可售 Y / 不在可售库 Z”，这是可售校验的加分点。
- 多网点（银行 3 支行 / 食品 3 商圈）：`anchor_bundles.json` 的成员各自取覆盖后并池；公交按线路、地铁按出口去重，重复候选取最近网点；距离归一化用该候选的 `localRadius`；触达按 `reachAnchor` 取对应网点 2023-05 文件，网点之间未去重。

### 3.3 打分

```text
score = 0.45 * distanceScore      // 越近越高
      + 0.25 * gradeScore         // S=1, A++=0.8, A+=0.6
      + 0.20 * availabilityScore  // freeCount / totalCount
      + 0.10 * efficiencyScore    // 1 / 净价
```

- 地铁权重 ×1.2（医院场景到达优先）。
- 同一条线路只选一次；同站点最多 2 个口。

### 3.4 选组合

- 目标：净价 ≤ 预算；媒体配比可配置（医院默认 地铁 55% / 公交 45%）。
- **预算滑块只改预算，不改周期**；周期由“档期”输入决定，默认跟行业 `defaultWindowId`（银行开门红、食品暑期、医院 Q2，6 周）。
- 贪心：按 score/price 排序，依次加入，直到预算或配比上限。
- 局部交换：用 1 个高价地铁换 2 个公交，或反之，提升 score 且不超预算。
- 输出 8–20 条，避免“只选 1 条”或“几百条”。

### 3.5 报价

```js
months = weeks / (52 / 12);
media = busN * busPrice * months + metroN * metroPrice * months;
prod = busN * 5000 + metroN * 2000;
total = (media + prod) * discount;
```

- 价格表见 HANDOFF 5.3；`discount=1.0` 默认，`0.92` 为可切换示例；页面必须标注“92 折示例假设，待销售确认”，不要写成公司政策。
- 预算 100/200/500 万；如果组合超预算，自动减数量/换低价级别，**不要靠缩短周期**来压价。

### 3.6 触达（预估）

- 公交：优先用 `data/footfall/<anchorId>_202305.json` 的线路 `dailyReach`（触达人次/天，2023-05）；没有平台数据时按 `busN * 9.8万/天 * days`（05 样本单车均值），标注“按历史样本预估”。
- 地铁：用同一文件的站点/出入口 `dailyReach`（2023-05）；同站多口不叠加，站点口径用 `aggregateReach`；无数据（世纪大道、迪士尼）显示 `—`，不要编“50 万/天”。
- 现有 5 份：陆家嘴、人民广场、徐家汇、美华、迪士尼；迪士尼只有公交，地铁 0 口。
- 页面统一写“2023 人流仅作相对权重，不代表 2027 绝对值”；没有数据就写“无数据”。

## 4. 验收标准

### 4.1 启动

```bash
cd 新云AI提案工作台
python -m http.server 8788
# 打开 http://127.0.0.1:8788/src/index.html
```

- 无控制台报错；无外部网络请求。
- 首屏 2 秒内出现输入面板 + 地图 + 方案。

### 4.2 预算三档

| 输入 | 期望 |
|---|---|
| 100 万 / 4 周 / 地铁+公交 | 约 8 辆公交 + 2 个地铁口（1.0）；92 折可到 10 辆 + 2 口；净价 ≤ 100 万 |
| 200 万 / 6 周 / 地铁+公交 | 约 10 辆公交 + 3 个地铁口（1.0）；92 折可到 12 辆 + 3 口；净价 ≤ 200 万 |
| 500 万 / 6 周 / 地铁+公交 | 约 34 辆公交 + 6 个地铁口（1.0，美华单点）；92 折可到 39 辆 + 6 口；净价 ≤ 500 万 |

允许 ±20% 的组合差异（因为库存/覆盖不同），但**绝不能超预算**，且数量级不能是 45+6 或 90+15。

### 4.3 现场应变

- 拖动预算 200→500→100：方案在 2 秒内更新；数量/组合变化；周期由档期单独控制，不随预算变；不刷新页面。
- 切换媒体“只地铁”：公交数量为 0，地铁数量增加；报价重算。
- 换行业（P0 可只换文案）：品牌洞察/合规提示变化，方案不崩。

### 4.4 证据

- 每条方案行显示：空车数、查询日期、最近距离、最近站点、选择理由。
- 顶部显示库存快照时间。
- 销售视图显示合同/预定/折扣底线/替补池。

### 4.5 导出

- CSV 能下载，列与方案表一致。
- HTML 导出能打开/打印，包含报价与清单。

### 4.6 视觉

- 参考 `docs/01_项目介绍.html`：纸色背景、深色地图、橙色信号、等宽数据字。
- 不要通用后台模板；地图是主视觉。
- 1440×900 不横向滚动；390px 可读。

## 5. 代码约束

- 纯 HTML/CSS/JS，ES modules 可选；不要 React/Vue 构建链。
- `engine.js` 导出纯函数：`selectPlan(inv, coverage, brief) -> plan`；方便测试。
- 金额用整数元，显示时转“万”；不要浮点误差影响预算判断（允许 1 元误差）。
- 所有中文文案集中在 `app.js`/`engine.js` 顶部常量，方便改行业。
- 注释简洁；不要写“AI 生成”之类空话。
- 不读取 `config.local.json`，不调用红豆/大数据 API。

## 6. 银行 P0（当前默认）

当前演示默认切到银行，配置已就绪：

- 行业：`bank-insurance`（`industries.json.defaultIndustryId`）
- 品牌：`spdb` / 浦发银行（上海浦东发展银行）
- 锚点：3 个真实支行 `spdb-shanghai-hq`（上海分行，浦东南路588号）、`spdb-jiujiang`（九江路支行，湖北路258号）、`spdb-xujiahui`（徐家汇支行，虹桥路188号），每点 1km；覆盖按网点坐标重抓，1km 合计 97 条（80 公交/17 地铁）
- 档期：默认 **开门红 2027-01-04～02-14（6 周）**；Q2 4/1–5/12 为备选；四档期库存均已导入
- 200 万 / 6 周（开门红，实测）：
  - 1.0：2 个地铁口 + 15 辆公交，194.8 万；三个网点均有选中
  - 92 折：3 个地铁口 + 12 辆公交，199.2 万
- 500 万 / 6 周：5 口 + 38 辆，499.6 万
- 100 万 / 6 周：1 口 + 8 辆，98.9 万；预算限制下只覆盖 2 个网点，页面会明示

银行文案要求：

- 客户版必须带“投资有风险”提示；
- 不写具体收益率、费率、产品名称；
- 不出现“保本、稳赚、无风险、保证收益”等承诺；
- 叙事：上海分行 / 浦发支行网络 / 财富管理；客群：上海分行、九江路支行、徐家汇支行三个网点周边 1km 的商务通勤与高净值。

验收：页面默认进入银行/浦发/3 真实支行；100/200/500 万可切换且不超预算；合规提示可见。

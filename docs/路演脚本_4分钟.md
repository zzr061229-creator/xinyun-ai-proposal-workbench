### 0:00–0:26 · 开场：把「两天」立起来

**口播（逐字）**

> 大家好，我们是 404 Not Found。先看一个真实场景：明年开门红，浦发银行要在上海三个支行周边一公里投 200 万，六周。换到今天，销售要开红豆查空位、翻刊例、在地图上圈线、再做 PPT——两天；客户改一次预算，全部重来。我们把它压成 90 秒。

**动作**：停在默认首屏，不操作，让评委先看清「银行 / 浦发 / 200 万 / 开门红」。

**别做**：不要一上来讲技术栈；先让评委感到「这活我熟、这痛我懂」。

### 0:26–1:06 · 答案先行 + 预算条

**口播（逐字）**

> 默认已经算完：两个地铁口、十五辆公交，净价 197.6 万，预算内还剩 2.4 万。锚点不是一个陆家嘴，是三个真实支行：上海分行、九江路支行、徐家汇支行，每个一公里。200 万先压在分行和徐家汇；隧道六线、隧道三线跨到九江路，两条线连两个圈。
>
> 这条预算条把 197.6 万按条目切开。我悬停哪一段，地图上对应线路就加粗，右边清单同时亮——钱花在哪，一眼看到。

**动作**

1. 手指答案行「2 个地铁口 + 15 辆公交」和右侧「净价 197.6 / 余额 2.4」。
2. 指地图上三个网点圈，再指「上海分行 / 九江路支行 / 徐家汇支行」标签。
3. 鼠标在「每一万块落在哪」预算条上从左到右悬停 2–3 段，让地图和右侧「方案条目」同步高亮。
4. 顺带指答案下方小字：「日均触达约 156.9 万人次（平台 2023-05，同站不相加）」。

**如果评委追问「九江路怎么只有两条线」**：200 万优先评分高的点位，九江路没有独立地铁口入选；隧道六线、隧道三线跨两个圈，是真实线路复用，不是硬塞。500 万时人民广场两个口会进来。

**口径**：触达说「2023 年平台数据，作相对权重」，不说成 2027 的承诺；地铁是「区域触达」，不是闸机客流。

### 1:06–1:36 · 账本 + 三层筛选

**口播（逐字）**

> 往下是账：刊例加制作费、乘折扣，得到净价，和 200 万预算线对着看。再往下是三层筛选：平台覆盖 97 条候选，红豆里可售 81 个线路和出入口，预算内选中 15 行。覆盖有、红豆没有的 5 项，我们明说「不在库」——4 条公交线加南京东路站，不塞给客户。

**动作**

1. 滚到「01 这笔账怎么算」，指瀑布图和「预算线」。
2. 滚到「02 从覆盖到方案，筛了三层」，依次指 **97 / 81 / 15**。
3. 指第二层小字里的「不在库」名单：旅游2线、旅游10线、旅游1线、911路双层、南京东路。
4. 指地图左上角角标：覆盖候选 97 / 可售 81 / 选中 15 / 不在库 5。

**口径**

- 「81」= 60 条可售公交线 + 21 个可售地铁口，按「线路 / 出入口」计；不要念成「81 条公交」。
- 「15 行」= 15 辆公交分在 13 条线上 + 2 个地铁口（页面按行数计）。
- 这一段是全场可信度的支点：**覆盖有、库存没有的，不悄悄丢，也不硬塞。**

## 6. 禁说清单

- 不说：「库存实时同步 / 已锁定」。
